Module I · CO1

Introduction to Data Structures

Remember: organize → operate → optimize

1. Data structure

A way to organize, store and manage data for efficient access and modification.

Primitive: int, char, float, boolean. Non-primitive: arrays, lists, stacks, queues, trees, graphs.

2. Classification

3. Core operations

Traverse visit · Insert add · Delete remove · Search find · Sort order · Update change.

4. Abstract Data Type (ADT)

Defines what operations do, not how they are implemented. Stack ADT: push, pop, peek. Can use array or linked list.

5. Time complexity

How runtime grows with input size n. Big-O examples:

O(1)O(log n)O(n)O(n log n)O(n²)

Usually from faster growth to slower efficiency: O(1), O(log n), O(n), O(n log n), O(n²).

6. Space complexity

Memory used as input grows. Fixed extra variables: O(1); extra array of n elements: usually O(n) auxiliary space.

7. Real-world selection

Browser back → StackPrinter jobs → QueueFolders → TreeRoad map/social network → GraphFast key lookup → Hash table

Choose a structure based on required operations, memory, data relationships and performance.

Module II · CO2

Stacks and Queues

Stack = LIFO · Queue = FIFO

1. Stack ADT

LIFO: last in, first out. Operations: push insert, pop remove top, peek/top view top, isEmpty test.

30 · TOP
20
10
Pop removes 30 first

Overflow = full fixed stack; underflow = pop from empty stack.

2. Stack implementations

Array: `top = -1` initially; push increments top; pop decrements it. Fixed capacity.

Linked list: top points to head; push/pop at head. Both operations O(1); grows until memory is exhausted.

3. Stack applications

Function calls/call stack, recursion, infix conversion, postfix evaluation, balanced brackets, undo-redo, browser back history.

Recursion needs a base case; otherwise stack overflow may occur.

4. Expressions

Infix: A+B · Prefix: +AB · Postfix: AB+

Infix `A+B*C` → postfix `ABC*+` because `*` has higher precedence.

Postfix evaluation: scan left→right, push operands; on operator pop right then left operand, calculate, push result.

5. Infix → postfix

Send operands directly to output. Use a stack for operators and parentheses. Pop higher-precedence operators first; respect associativity. Parentheses control when to pop.

Bracket check: push opening brackets; each closer must match the latest opener; stack must finish empty.

6. Queue ADT

FIFO: first in, first out. Enqueue at rear, dequeue at front, front/peek reads first element.

Applications: printer queue, task scheduling, network packets.

7. Linear vs circular queue

Linear array queue: front/rear indices; freed front slots may be wasted (false overflow).

Circular queue: rear wraps around. Next position = `(rear+1) % size`; reuses free slots. Enqueue/dequeue typically O(1).

8. Priority queue & deque

Priority queue: served by priority (max or min); equal priorities may use arrival order.

Deque: insert/delete at both ends. Input-restricted = insertion at one end; output-restricted = deletion at one end.

9. Queue/stack conversions

Stack using 2 queues: costly-push method: push O(n), pop O(1).

Queue using 2 stacks: input stack receives items; transfer to output stack only when output is empty. Amortized O(1) per operation.

10. Self-learning topics

Undo/redo: undo stack reverses latest action; redo stack restores it; a new action usually clears redo history. Prefix→postfix: scan prefix right→left; push operands; on operator pop two expressions and combine as `operand1 operand2 operator`.

Module III · CO3

Linked Lists

Nodes + links

1. Basics & representation

Dynamic linear structure of nodes. Each node stores data and pointer(s); `head` points to first node; empty list: `head = NULL`.

NULL

2. Types

Singly: next pointer, forward only.

Doubly: prev + next, both directions.

Circular: last points to first; stop when start is reached again.

3. Array vs linked list

Array: contiguous memory, index access O(1), middle insert/delete may shift items.

Linked list: nodes need not be contiguous, index access O(n), extra pointer memory; known-position link updates can be O(1).

4. Singly linked operations

Traversal/search: follow `next` until NULL, worst-case O(n). Insert/delete at head: O(1). Can insert at end or after a node; delete first, last or target node with correct pointer handling.

5. Doubly linked operations

Update both `next` and `prev` links during insertion/deletion. Efficient backward traversal; extra memory per node. Useful in browser navigation and playlists.

6. Stack/queue using list

Stack: `top = head`; push/pop at head, O(1).

Queue: maintain `front` and `rear`; enqueue at rear, dequeue at front, O(1). If last node removed, set both pointers to NULL.

7. Reverse a linked list

Use `prev`, `current`, `next`. Save next; point current back to prev; advance all pointers. At end, prev is new head.

Time O(n)Extra space O(1)

8. Merge sorted lists

Compare first remaining nodes, attach the smaller one, repeat; append the leftover list. For sizes n and m: O(n+m) time.

9. Polynomial representation

Each node stores coefficient, exponent. Example: 5x²+3x+7 → (5,2)→(3,1)→(7,0). Add terms with equal exponents by adding coefficients.

10. Applications & quick facts

Linked lists suit dynamic collections, stacks/queues, playlists and navigation. Head = first node; tail = last node; NULL = no next node in a non-circular list. Pointer mistakes can lose access to the remaining list, so save links before changing them.

Module IV · CO4

Trees

Root · branches · leaves

1. Terminology

Root: top node · parent/child: directly connected levels · sibling: same parent · leaf: no children · degree: number of children · depth: edges from root · height: longest downward path.

A tree with n nodes has n−1 edges; no cycles.

2. Binary tree & types

Each node has at most two children: left and right. Full: each node has 0 or 2 children. Complete: levels filled except possibly last, filled left-to-right. Perfect: all internal nodes have 2 children and leaves share a level.

3. Representation

Array, zero-indexed: left = 2i+1; right = 2i+2; parent = floor((i−1)/2).

Linked: each node stores data + left/right pointers. Arrays suit complete trees; linked nodes suit flexible shapes.

4. Traversals

Preorder: Root, Left, Right.

Inorder: Left, Root, Right.

Postorder: Left, Right, Root.

For A with children B,C: preorder A-B-C; inorder B-A-C; postorder B-C-A.

5. Binary Search Tree (BST)

Left keys < node < right keys (distinct-key convention). Inorder gives sorted order. Search/insert: O(h), average O(log n), worst O(n) if skewed.

6. BST insertion/search/deletion

Insert/search: compare, go left if smaller, right if greater.

Delete: leaf → remove; one child → link parent to child; two children → replace with inorder successor (smallest right-subtree key) or predecessor (largest left-subtree key).

7. AVL tree & balance

Self-balancing BST. Balance factor:

BF = height(left) − height(right)

Allowed values: −1, 0, +1. Search/insert/delete: O(log n). Insert by BST rules, then rebalance ancestors.

8. AVL rotations

LL: right rotation. RR: left rotation. LR: left child left-rotate, then node right-rotate. RL: right child right-rotate, then node left-rotate.

Example 30,20,10 → LL; right-rotate 30; 20 becomes root.

9. Expression & Huffman trees

Expression tree: operators internal, operands leaves; preorder=prefix, inorder=infix, postorder=postfix.

Huffman: repeatedly combine two lowest-frequency nodes; frequent symbols get shorter prefix-free codes. Used for lossless compression.

10. B-Tree & B+ Tree

B-Tree: balanced multiway search tree, multiple keys/node; full node splits and middle key is promoted.

B+ Tree: records/pointers typically in leaves, internal nodes guide search; linked leaves help range queries. Both used in databases/file systems.

11. Threaded trees & file systems

Threaded binary tree: uses otherwise-NULL pointers for inorder predecessor/successor, allowing traversal without recursion or an auxiliary stack. File system: folders and files form a hierarchy represented naturally by a tree.

Module V · CO5

Graphs

Vertices + edges

1. Graph basics

Graph G=(V,E): V = vertices/nodes, E = edges. Directed: edges have direction. Undirected: no direction. Weighted: edges have costs. Degree = connected edges; directed graph uses indegree/outdegree.

2. Graph types

Simple: no loops/multiple edges. Connected: path between every vertex pair (undirected). Complete: every pair connected. Cyclic: has a cycle. DAG: directed acyclic graph.

3. Adjacency matrix

V×V table; entry 1 means edge exists (or stores weight). Edge check O(1), space O(V²). Good for dense graphs.

A-BA-CMatrix = grid

4. Adjacency list

Each vertex stores its neighbours. Space typically O(V+E); good for sparse graphs. Undirected edge normally appears in both endpoints' lists.

5. BFS

Visits level by level; uses a queue + visited set/array. Finds shortest path by edge count in unweighted graphs.

6. DFS

Explores one path deeply, then backtracks; uses recursion or stack. Uses: cycle detection, connected components, maze solving, topological sort. Adjacency list: O(V+E).

7. BFS vs DFS

BFS: queue, level-by-level, shortest unweighted path. DFS: stack/recursion, deep then backtrack, no general shortest-path guarantee. Both O(V+E) with adjacency list.

8. Topological sorting

Order vertices of a DAG so every u→v has u before v. Methods: Kahn's algorithm (indegree-zero queue) or DFS finish order. A directed cycle means no valid topological ordering.

9. Dijkstra's algorithm

Single-source shortest paths with non-negative edge weights. Set source distance 0, others ∞; repeatedly choose smallest tentative distance and relax outgoing edges. Priority queue improves efficiency. Not valid for negative-weight edges.

10. Real-world applications

Maps: locations=vertices, roads=edges, weights=distance/time; shortest-path methods help route planning. Networks: computers/routers=vertices, links=edges; graphs support routing, connectivity checks and network design.

Module VI · CO6

Searching and Sorting

Find · arrange · hash

1. Searching

Find a target/key in data. Choice depends on sorting, data layout and distribution. Main methods: linear, binary, interpolation and hash lookup.

2. Linear search

Check elements one by one; works sorted or unsorted. Best O(1), worst O(n). Simple and useful for small/unsorted collections.

4→8→Target?

3. Binary search

Compare middle; discard half each step. Requires sorted data and efficient random access. Time O(log n); iterative extra space O(1).

4. Hashing & hash function

Hash function maps key to table index. Example: `key % table_size`. Good function is fast and spreads keys evenly. Hashing average operations O(1), worst O(n).

5. Collision resolution

Collision: different keys map to same slot.

Separate chaining: bucket/list per slot.

Open addressing: probe for another slot.

6. Open addressing methods

Linear: h(k)+i; simple, primary clustering.

Quadratic: h(k)+c₁i+c₂i²; reduces primary, may have secondary clustering.

Double hashing: h₁(k)+i·h₂(k); good spread; step should cover table.

Use modulo table size for index.

7. Load factor & rehashing

α = entries / table capacity

When table gets crowded, create a larger table and reinsert keys using new indices. One rehash O(n); geometric growth can give amortized O(1) insertion.

8. Bubble sort

Compare adjacent elements and swap; largest unsorted element bubbles to end. Best O(n) with early exit; average/worst O(n²). Stable if equals are not swapped.

9. Selection sort

Find minimum in unsorted portion and swap into next position. Best/average/worst O(n²), auxiliary O(1). Few swaps; standard version not stable.

10. Insertion sort

Take next item, shift larger sorted items right, insert in correct place. Best O(n), average/worst O(n²); stable. Good for small or nearly sorted data.

11. Merge sort

Divide into halves, sort recursively, merge sorted halves. Best/average/worst O(n log n); array version typically needs O(n) extra space. Stable with careful merging.

12. Quick sort

Choose pivot, partition smaller/larger elements, recursively sort parts. Average O(n log n), worst O(n²); performance depends on pivot and partition balance.

13. Interpolation search

Sorted numeric data; estimates target position from values. Average can be O(log log n) for near-uniform data, worst O(n). Handle equal endpoints and divide-by-zero safely.
